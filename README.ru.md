# openwrt-openvpn-install

[English](README.md) | **Русский**

Установщик сервера OpenVPN для роутеров на OpenWrt, написанный специально под
OpenWrt: BusyBox `ash`, `opkg` или `apk`, вся настройка через UCI.

При первом запуске скрипт ставит пакеты, создаёт удостоверяющий центр (CA),
настраивает сервер OpenVPN, сетевой интерфейс и межсетевой экран, а затем
создаёт первого клиента. При повторном запуске он показывает меню:

```
1) Add a new client
2) Revoke an existing client
3) Remove OpenVPN
4) Exit
```

- `1) Add a new client` — добавить клиента;
- `2) Revoke an existing client` — отозвать клиента;
- `3) Remove OpenVPN` — удалить OpenVPN;
- `4) Exit` — выход.

Каждый клиент получает один файл `.ovpn`, в который встроено всё необходимое
(CA, сертификат, ключ, ключ tls-crypt/tls-auth). Файл сохраняется как
`<каталог клиентов>/<name>.ovpn` (каталог выбирается при установке, по
умолчанию `/root`).

## Требования

- OpenWrt 22.03 или новее (22.03, 23.05 и 24.10 используют `opkg`; 25.12 и новее — `apk`).
- Root-доступ к роутеру (SSH).
- Около 6 МБ свободной флеш-памяти под пакеты (скрипт для надёжности
  проверяет наличие 8 МБ и ставит только недостающие пакеты).
- Доступ роутера в интернет во время установки — для загрузки пакетов.
- Правильно выставленные часы роутера: от них отсчитывается срок действия
  сертификатов. Если год меньше 2024, скрипт предупредит.

Используемые пакеты: `openvpn-openssl` и `openvpn-easy-rsa` (он подтягивает
`openssl-util`), а также `luci-app-openvpn`, если вы попросите веб-страницу.
Если уже установлен другой вариант OpenVPN (`openvpn-mbedtls`,
`openvpn-wolfssl`), скрипт использует его.

## Использование

Скачайте скрипт и запустите его (в OpenWrt `wget` предоставляется через
`uclient-fetch`):

```sh
wget -O openvpn-install.sh https://raw.githubusercontent.com/Lenvix/openwrt-openvpn-install/main/openvpn-install.sh && sh openvpn-install.sh
```

Не передавайте скрипт в `sh`
через конвейер (`| sh`): для вопросов нужен терминал, и без него скрипт
отказывается работать, если не включён режим без участия пользователя
(headless).

### Вопросы при установке

Нажмите Enter, чтобы принять значение по умолчанию, показанное в
`[квадратных скобках]`.

1. **Имя экземпляра** (`Instance name (letters, digits and _)`). Имя
   экземпляра OpenVPN: под ним он виден в LuCI (VPN → OpenVPN), а ключи и
   PKI кладутся в `/etc/openvpn/<имя>/`. По умолчанию `openvpninstall`.
   Своё имя может состоять из латинских букв, цифр и `_`, не может
   начинаться с цифры, длина — не более 32 символов. Кроме того, ещё не
   должно существовать ни секции UCI `openvpn.<имя>`, ни каталога
   `/etc/openvpn/<имя>`, ни файла `/etc/openvpn/<имя>.ovpn` или
   `/etc/openvpn/<имя>.conf`.
2. **Как хранить конфигурацию сервера**
   (`How should the server configuration be stored?`).
   1. **Форма LuCI** (по умолчанию): каждая опция — отдельная настройка UCI
      в секции `<имя>` файла `/etc/config/openvpn`; в LuCI она правится по
      полям (VPN → OpenVPN → Edit).
   2. **Текстовый файл**: опции записываются в `/etc/openvpn/<имя>.ovpn` —
      туда же, где текстовые конфигурации хранит сам LuCI. В секции UCI
      остаются только `enabled` и `option config '/etc/openvpn/<имя>.ovpn'`,
      а LuCI показывает файл в поле для редактирования текста. После
      установки скрипт этот файл больше не перезаписывает, так что ваши
      правки сохраняются. Но при добавлении и отзыве клиентов скрипт берёт
      адрес сервера, порт, протокол и шифр, запомненные при установке: если
      поменять в файле порт, протокол или шифр, новые клиентские файлы всё
      равно получат старые значения.

   В обоих режимах сервер запускается через `/etc/init.d/openvpn`.
3. **Публичный адрес** (`Public address or hostname`). По умолчанию — IPv4-адрес
   WAN. Если этот адрес частный или CGNAT (например, 192.168.x.x или
   100.64.x.x), скрипт предупредит и предложит узнать публичный IP через
   `api.ipify.org`. Можно также указать DDNS-имя.
4. **Порт** (`Which port should OpenVPN listen on?`). 1194 (по умолчанию),
   свой порт или случайный порт в диапазоне 49152–65535.
5. **Протокол** (`Which protocol should OpenVPN use?`). UDP (по умолчанию)
   или TCP.
6. **Режим маршрутизации** (`What should VPN clients be able to reach?`).
   См. ниже.
7. **Подсеть VPN** (`VPN subnet network address`). Для VPN-интерфейса
   создаётся отдельная подсеть `/24`. Скрипт предлагает первую свободную,
   начиная с `10.8.0.0/24`; свободной считается подсеть, которая не
   пересекается ни с одним IPv4-адресом и ни с одним маршрутом на роутере.
   Можно ввести свою частную `/24` — она проверяется точно так же. Роутер
   занимает в этой подсети адрес `.1`, клиенты получают адреса начиная с
   `.2`.
8. **Имя VPN-интерфейса** (`Interface name`). Одно имя используется и для
   сетевого интерфейса OpenWrt, и для его зоны межсетевого экрана. По
   умолчанию `vpn`; если `vpn` уже занято существующим сетевым интерфейсом
   или зоной межсетевого экрана, скрипт предложит `vpn1`, `vpn2` и т. д.
   Допустимы латинские буквы, цифры и `_`; имя не может начинаться с цифры,
   длина — не более 11 символов, и оно не должно совпадать с уже
   существующим интерфейсом или зоной. Устройство tun выбирается
   автоматически — первое свободное `tunN` (tun0, tun1, …), поэтому сервер
   уживается с другим VPN, который уже занял tun0.
9. **DNS для клиентов** (`Which DNS server should clients use?`). Сам роутер
   (dnsmasq на адресе VPN-шлюза, по умолчанию), Cloudflare, Quad9, Google,
   AdGuard DNS или свои серверы.
10. **Сжатие** (`Enable compression?`). По умолчанию выключено. Включать его
   не рекомендуется (атака VORACLE), и из OpenVPN оно удаляется. Можно
   выбрать LZ4-v2, LZ4 или LZO.
11. **Шифрование** (`Customize encryption settings?`). По умолчанию:
   сертификаты ECDSA `prime256v1`, шифр канала данных `AES-128-GCM`, HMAC
   `SHA256` и `tls-crypt`. Если выбрать собственную настройку, можно задать:
   - шифр: AES-128/192/256-GCM или CHACHA20-POLY1305;
   - тип сертификата: ECDSA с кривой `prime256v1`, `secp384r1` или `secp521r1` либо RSA на 2048, 3072 или 4096 бит;
   - HMAC: SHA256, SHA384 или SHA512;
   - защиту канала управления: `tls-crypt` или `tls-auth`.
12. **Страница LuCI** (`Install the LuCI web page for OpenVPN (...)?`).
    Ставить ли `luci-app-openvpn` (VPN → OpenVPN в веб-интерфейсе). По
    умолчанию «да», если LuCI установлен, и «нет», если нет — иначе пакет
    подтянет LuCI за собой. Если пакет уже стоит, вопрос пропускается.
13. **Каталог для клиентских файлов .ovpn**
    (`Directory for client .ovpn files`). По умолчанию `/root`. Абсолютный
    путь из латинских букв, цифр, `.`, `_`, `-` и `/` (но не сам `/`). Если
    каталога нет, он создаётся; выбранный каталог запоминается и для
    клиентов, добавленных позже.
14. **Срок действия сертификатов клиентов по умолчанию**
    (`Default certificate lifetime for new clients, in days`). В днях, 1–3650
    (по умолчанию 3650). Запоминается и предлагается для каждого следующего
    клиента.
15. **Первый клиент** (`Client name (letters, digits, _ and -)`). Имя из букв,
    цифр, `_` и `-`, срок действия его сертификата в днях
    (`Certificate lifetime for '<имя>', in days`; по умолчанию — из предыдущего
    вопроса), а также защищать ли ключ клиента паролем
    (`Protect the client key with a password?`).

При добавлении клиента из меню скрипт тоже спрашивает срок в днях, предлагая
запомненный, а после выпуска показывает дату окончания. CA и сертификат
сервера действуют 10 лет; список отзыва (CRL) при каждом формировании тоже
выпускается на 10 лет. После окончания срока CA сертификат клиента
перестаёт работать, каким бы ни был его собственный срок.

## Режимы маршрутизации

| # | Режим | Пересылка в межсетевом экране | Что передаётся клиентам |
|---|-------|-------------------------------|-------------------------|
| 1 | **Весь трафик** (по умолчанию) | vpn → lan, vpn → wan | `redirect-gateway def1 bypass-dhcp`, DNS |
| 2 | **Только интернет (wan)** | vpn → wan | `redirect-gateway def1 bypass-dhcp`, DNS; доступа в LAN нет |
| 3 | **Только LAN** | vpn → lan | маршруты к подсети (подсетям) LAN из интерфейса `lan`, DNS; интернет у клиента идёт напрямую |
| 4 | **Без пересылки** | нет | DNS; клиентам доступен только сам роутер (адрес VPN-шлюза) |

Здесь `vpn` — зона VPN-интерфейса (её имя задаётся в вопросе 8). В любом
режиме эта зона принимает входящие соединения, поэтому клиенты всегда могут
обратиться к самому роутеру, в том числе к его DNS-серверу.

## Режим без участия пользователя (headless)

### Установка

Задайте `AUTO_INSTALL=y`. Тогда на каждый вопрос берётся значение по
умолчанию, если оно не переопределено соответствующей переменной из таблицы
ниже.

```sh
AUTO_INSTALL=y sh openvpn-install.sh
AUTO_INSTALL=y ENDPOINT=vpn.example.org PROTOCOL_CHOICE=2 PORT=443 ROUTE_MODE=2 CLIENT=laptop sh openvpn-install.sh
```

| Переменная | Значения | По умолчанию |
|------------|----------|--------------|
| `APPROVE_INSTALL` | `y` / `n` | `y` |
| `INSTANCE_NAME` | имя экземпляра `[A-Za-z_][A-Za-z0-9_]*`, не более 32 символов, не занято | `openvpninstall` |
| `CONFIG_FORMAT` | `1` форма LuCI (настройки UCI), `2` текстовый файл `/etc/openvpn/<экземпляр>.ovpn` | `1` |
| `ENDPOINT` | публичный IPv4 или имя хоста | IPv4 WAN, если он публичный, иначе узнаётся через api.ipify.org |
| `DETECT_PUBLIC_IP` | `y` / `n` (узнавать публичный IP, если адрес WAN частный) | `y` |
| `PORT_CHOICE` | `1` 1194, `2` свой (`PORT`), `3` случайный | `1` (`2`, если задан `PORT`) |
| `PORT` | 1-65535 | 1194 |
| `PROTOCOL_CHOICE` | `1` UDP, `2` TCP | `1` |
| `ROUTE_MODE` | `1` весь трафик, `2` только интернет, `3` только LAN, `4` без пересылки | `1` |
| `VPN_SUBNET` | адрес частной сети `/24`, например `10.9.0.0` | первая свободная начиная с `10.8.0.0` |
| `VPN_IFACE` | имя интерфейса и зоны: `[A-Za-z_][A-Za-z0-9_]*`, не более 11 символов, не занято | первое свободное из `vpn`, `vpn1`, … |
| `DNS` | `1` роутер, `2` Cloudflare, `3` Quad9, `4` Google, `5` AdGuard, `6` свои | `1` |
| `DNS1`, `DNS2` | IPv4-адреса для `DNS=6` (`DNS2` необязателен) | нет |
| `COMPRESSION_ENABLED` | `y` / `n` | `n` |
| `COMPRESSION_CHOICE` | `1` lz4-v2, `2` lz4, `3` lzo | `1` |
| `CUSTOMIZE_ENC` | `y` / `n` | `n` |
| `CIPHER_CHOICE` | `1` AES-128-GCM, `2` AES-192-GCM, `3` AES-256-GCM, `4` CHACHA20-POLY1305 | `1` |
| `CERT_TYPE` | `1` ECDSA, `2` RSA | `1` |
| `CERT_CURVE_CHOICE` | `1` prime256v1, `2` secp384r1, `3` secp521r1 | `1` |
| `RSA_KEY_SIZE_CHOICE` | `1` 2048, `2` 3072, `3` 4096 | `1` |
| `HMAC_ALG_CHOICE` | `1` SHA256, `2` SHA384, `3` SHA512 | `1` |
| `TLS_SIG_CHOICE` | `1` tls-crypt, `2` tls-auth | `1` |
| `INSTALL_LUCI` | `y` / `n` (ставить `luci-app-openvpn`) | `y`, если LuCI установлен, иначе `n` |
| `CLIENT_FILES_DIR` | абсолютный путь к каталогу клиентских файлов `.ovpn` | `/root` |
| `CLIENT_DAYS_DEFAULT` | срок сертификатов клиентов по умолчанию, дней 1–3650 | `3650` |
| `CLIENT_DAYS` | срок сертификата первого клиента, дней 1–3650 | `CLIENT_DAYS_DEFAULT` |
| `CLIENT` | имя первого клиента `[A-Za-z0-9_-]+` | `client` |
| `PASS` | `1` без пароля, `2` с паролем (только интерактивно) | `1` |

Переменные шифрования (от `CIPHER_CHOICE` до `TLS_SIG_CHOICE`) учитываются
только при `CUSTOMIZE_ENC=y`. Значение, не прошедшее проверку, останавливает
скрипт с ошибкой. Это касается и интерактивного запуска: если какая-либо из
этих переменных уже задана, соответствующий вопрос пропускается.

### Управление существующей установкой

Задайте `MENU_OPTION`, чтобы ответить на меню без терминала:

```sh
MENU_OPTION=1 CLIENT=phone sh openvpn-install.sh            # add client "phone" (passwordless)
MENU_OPTION=2 CLIENT=phone sh openvpn-install.sh            # revoke client "phone"
MENU_OPTION=3 sh openvpn-install.sh                         # remove OpenVPN (keeps packages)
MENU_OPTION=3 REMOVE_PACKAGES=y sh openvpn-install.sh       # remove OpenVPN and the packages it installed
```

По порядку: добавить клиента `phone` (без пароля); отозвать клиента `phone`;
удалить OpenVPN, оставив пакеты; удалить OpenVPN вместе с пакетами, которые
поставил установщик.

| Переменная | Для пункта | Назначение |
|------------|------------|------------|
| `MENU_OPTION` | все | `1` добавить, `2` отозвать, `3` удалить, `4` выход |
| `CLIENT` | 1, 2 | имя клиента (обязательно) |
| `CLIENT_DAYS` | 1 | срок сертификата в днях, 1–3650 (по умолчанию — выбранный при установке) |
| `PASS` | 1 | `1` без пароля (по умолчанию); для `2` нужен терминал |
| `REMOVE_CONFIRM` | 3 | `y` (по умолчанию в headless-режиме) / `n` |
| `REMOVE_PACKAGES` | 3 | `y` / `n` (по умолчанию `n`) |

## Что скрипт меняет на роутере

Все изменения вносятся через UCI. У каждой секции имя, принадлежащее
скрипту, и при удалении стираются ровно эти секции. Ниже `<экземпляр>` —
имя экземпляра из вопроса 1 (по умолчанию `openvpninstall`),
`<каталог клиентов>` — каталог из вопроса 13 (по умолчанию `/root`),
`<iface>` — имя, выбранное в вопросе 8 (по умолчанию `vpn`), а `<tunN>` —
автоматически выбранное устройство tun (первое свободное, обычно `tun0`).

| Где | Что |
|-----|-----|
| `/etc/config/openvpn` | секция `<экземпляр>` (тип `openvpn`): экземпляр сервера. В режиме формы LuCI в ней лежат штатные опции init-скрипта (`dev <tunN>`, `server`, `topology subnet`, `tls_crypt`/`tls_auth`, `crl_verify`, `data_ciphers`, `list push`, `user nobody`, ...), в режиме текстового файла — только `enabled` и `config '/etc/openvpn/<экземпляр>.ovpn'`. Секция `ovpninstall_meta` (тип `ovpninstall`): собственное состояние установщика (имя экземпляра, способ хранения конфигурации, каталог клиентов, шаблон клиента — протокол, порт, auth, шифр, tls-crypt/tls-auth, сжатие; адрес сервера, режим маршрутизации, имя интерфейса и устройство tun, параметры сертификатов, поставленные им пакеты, менял ли он dnsmasq). Init-скрипт эту секцию игнорирует. |
| `/etc/config/network` | интерфейс `<iface>`: `proto none`, `device <tunN>` |
| `/etc/config/firewall` | зона `ovpninstall_zone` (name `<iface>`, network `<iface>`, input/output ACCEPT, forward REJECT); правило `ovpninstall_rule` (`Allow-OpenVPN-<экземпляр>`: выбранные порт/протокол из `wan` на роутер); пересылки `ovpninstall_fwd_lan` и/или `ovpninstall_fwd_wan` в зависимости от режима маршрутизации |
| `/etc/config/dhcp` | только если DNS-сервером для клиентов служит роутер, а dnsmasq ограничен явным списком `interface`: в этот список добавляется `<iface>`. При стандартной конфигурации (`localservice`, без списка интерфейсов) dnsmasq и так отвечает в подсети VPN, и ничего не меняется. |
| `/etc/openvpn/<экземпляр>/` | `pki/` (PKI easy-rsa), `server/` (CA, сертификат и ключ сервера, TLS-ключ, CRL с правом чтения для `nobody`), `easyrsa-vars` |
| `/etc/openvpn/<экземпляр>.ovpn` | только в режиме текстового файла: конфигурация сервера (права 600) |
| `<каталог клиентов>/<name>.ovpn` | файлы конфигурации клиентов |
| `/etc/sysupgrade.conf` | строка `/etc/openvpn/<экземпляр>/`, а в режиме текстового файла ещё и `/etc/openvpn/<экземпляр>.ovpn` |

Служба OpenVPN включается и перезагружается. procd запускает и
останавливает только этот экземпляр (`<экземпляр>`), так что другие экземпляры
OpenVPN продолжают работать.

## Отзыв клиентов

При отзыве клиента скрипт отзывает его сертификат, заново формирует CRL,
копирует его в файл, на который указывает `crl_verify`, и удаляет
`<каталог клиентов>/<name>.ovpn`. OpenVPN перечитывает CRL при каждом TLS-рукопожатии,
поэтому перезапуск не нужен. Отозванный клиент, который ещё подключён,
отключится при следующем пересогласовании ключей — не позже чем через час.

## Sysupgrade

`/etc/config/*`, `/etc/openvpn/<экземпляр>/` (ключи, сертификаты и PKI)
и, в режиме текстового файла, `/etc/openvpn/<экземпляр>.ovpn` переживают
sysupgrade. **Пакеты — нет**. Клиентские файлы `.ovpn` сохраняются, только
если их каталог сохраняется при sysupgrade; каталог по умолчанию `/root` не
сохраняется. После sysupgrade поставьте пакеты заново:

```sh
opkg update && opkg install openvpn-openssl openvpn-easy-rsa   # 22.03 - 24.10
apk update && apk add openvpn-openssl openvpn-easy-rsa         # 25.12+
/etc/init.d/openvpn enable && /etc/init.d/openvpn start
```

Существующие клиентские файлы продолжают работать. Чтобы восстановить
потерянный файл `.ovpn`, отзовите этого клиента и добавьте его снова.

## Удаление

Запустите скрипт и выберите **3) Remove OpenVPN** (удалить OpenVPN) или
выполните `MENU_OPTION=3 sh openvpn-install.sh`. При удалении скрипт:

- удаляет экземпляр OpenVPN `<экземпляр>` и секцию состояния
  `ovpninstall_meta`, что останавливает экземпляр;
- выключает службу OpenVPN, если до установки она не была включена;
- удаляет сетевой интерфейс VPN (`<iface>`), зону, правило и пересылки
  межсетевого экрана, а также изменение dnsmasq, если оно вносилось;
- удаляет `/etc/openvpn/<экземпляр>/`, текстовый файл конфигурации
  `/etc/openvpn/<экземпляр>.ovpn` (в режиме текстового файла), клиентские
  файлы `.ovpn` в `<каталоге клиентов>` (сам каталог остаётся) и строки в
  `sysupgrade.conf`;
- перезагружает network, firewall, dnsmasq (если он менялся) и OpenVPN;
- предлагает удалить пакеты, которые поставил установщик. Пакеты, стоявшие
  до установки, не удаляются никогда.

## Ограничения

- Только IPv4. Туннель передаёт IPv4. В режимах маршрутизации 1 и 2
  IPv6-трафик клиента идёт мимо VPN.
- Подсеть VPN всегда `/24`.
- Поддерживается init-скрипт OpenVPN из OpenWrt 22.03–25.12. Сборки, где
  OpenVPN управляется только через netifd, без `/etc/init.d/openvpn`,
  скрипт не поддерживает и отказывается работать.
- Ключи клиентов с паролем требуют интерактивного терминала: пароль
  запрашивает easy-rsa.
